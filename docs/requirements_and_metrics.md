## 2. 设计原则

1. **所有指标都有明确公式和可调阈值**，阈值写在 YAML 配置里，报告里自动记录所用参数（可复现、可写进方法学）。
2. **与商业软件可对照**：同一段仪器视频，我们的结果与 ZebraLab / EthoVision 导出的结果做相关性验证（目标 r ≥ 0.95），这样已有的数据和新数据可以混用。
3. **输出分层**：帧级轨迹 → 片段（bout）级 → 时间分箱级 → 区域级 → 试次级 → 组级统计。任何上层指标都能追溯到下层。
4. **同一套引擎、不同预设**：幼鱼/成鱼/手机/仪器只是配置不同，核心代码只有一份。

## 3. 指标清单

**层级说明**：F = 逐帧；B = 每个游动片段（bout）；T = 时间分箱（如每 60 s）；Z = 每个区域；E = 每次刺激事件；S = 整个试次汇总。
**对象**：L = 幼鱼，A = 成鱼。
阈值一栏的数值是常见默认值，**都需要你按实验室现行 ZebraLab / EthoVision 设置确认 [待确认]**。

## 4. 录像条件：仪器 vs 手机 / 运动相机

### 4.1 仪器视频（第一阶段使用）
- Zebrabox：可导出 AVI 原始视频 + ZebraLab xls 结果；红外背光，光暗实验可用。
- DanioVision：可导出视频 + EthoVision 轨迹（逐帧 X/Y）和结果表。
- **这是验证我们算法的金标准数据来源 [待确认：能否各导出 1–2 个试次的视频 + 结果表]**。

### 4.2 手机 / 运动相机需要解决的问题

| 问题 | 影响 | 方案 |
|---|---|---|
| 镜头畸变（广角/鱼眼） | 边缘孔位置和距离失真可达 5–15% | 棋盘格标定（OpenCV 针孔 + Brown 畸变模型；GoPro 用鱼眼模型），一次标定、同机型复用 |
| 透视（相机不垂直于板面） | 距离各处比例不一致 | 用板的四角或打印的参考矩形做单应变换矫正 + 像素/mm 标定 |
| 可变帧率 VFR | 手机视频帧间隔不恒定，速度计算出错 | 读取每帧时间戳（ffprobe），按真实时间戳计算，或重采样为恒定帧率 |
| 自动曝光 / 对焦 / 白平衡漂移 | 背景模型失效、误检 | 拍摄 SOP：专业模式锁定 AE/AF/WB，固定支架 |
| 分辨率 vs 帧率 | 4K 只有 30/60 fps；240 fps 只有 1080p | 运动学指标 60 fps 足够；姿态级需另行拍摄（§5） |
| **红外** | **手机摄像头滤除红外，暗相位无法成像** | 光暗实验（VMR）用手机不可行；可选：去红外滤镜的改装相机 / 树莓派 + IR 摄像头（也很便携，成本低） [待确认] |
| 编码（HEVC/H.265）、手机竖拍旋转元数据 | 读取失败或方向错 | ffmpeg 预处理统一转码 |

### 4.3 建议的手机拍摄 SOP（草案）
固定支架正上方垂直拍摄 → 板下白色 LED 背光 → 专业模式锁定 ISO/快门/对焦/白平衡 → 1080p 60 fps（运动学）或 1080p 240 fps（尾部）→ 视野内放一张打印的标定参考（已知尺寸矩形 + 棋盘格角）→ 开始前拍 2 s 空板（背景）。

## 5. 姿态级分析的可行性

| 目标 | 手机 1080p 240 fps（近距离/宏镜头，少数孔） | 仪器相机（25–60 fps） | 高速相机（≥ 1000 fps） |
|---|---|---|---|
| 尾部中线、弯曲角 | 可行 | 仅粗略（bout 内只有 1–3 帧） | 可行 |
| 尾摆频率/幅度 | 可行（240 fps ≈ 每周期 4–10 帧，边缘可用） | 不可行 | 可行 |
| bout 细分类（J-turn 等） | 基本可行 | 不可行 | 可行 |
| C-start 最大弯曲角 | 低估（C 弯 ~8 ms 内完成，仅 2 帧） | 不可行 | 可行 |
| C-start SLC/LLC 潜伏期 | 不可行（4 ms/帧，分不开） | 不可行 | 可行 |
| 眼角 / 会聚 | 仅单孔 + 宏镜头 | 需专用放大 | 需专用放大 |

**结论**：姿态模块值得做，但要分两档：(a) 尾部运动学（手机 240 fps 可做）；(b) C-start 精细动力学与眼动（需要高速相机 / 显微放大）。**[待确认：实验室有没有高速相机或带放大的拍摄条件？]**

技术路线：先用经典方法（背景减除 → 骨架化 → 中线 → 角度），幼鱼高对比度下很稳，不需要训练模型；成鱼或复杂背景再引入轻量姿态模型（DeepLabCut/SLEAP 风格）。

## 6. 平台架构建议

```
手机/相机/仪器视频
      │
      ▼
[核心引擎 zfbehavior (Python)]  ← 唯一的算法实现，配置驱动
      │  track → metrics → stats → plots → report
      ├── 命令行 zfb：单文件 / 批量 / 并行，实验室电脑或服务器
      ├── Web 服务（FastAPI）：浏览器上传视频 → 排队处理 → 在线查看结果与下载
      │      └── 手机浏览器即可使用 = "手机分析"（第一版）
      └── （后期）桌面打包 / 手机端本地计算
```

- **"手机分析"第一版 = 手机录完直接在浏览器上传到实验室电脑/服务器**，几分钟出结果。手机本地跑算法（原生 App）是另一个量级的工程，建议放最后，等指标和算法稳定后再决定是否需要。**[待确认]**
- 批量：一个文件夹 + 一张样品表（视频 ↔ 分组/剂量/孔位）→ 全部试次 → 汇总表 + 组间统计 + 图。

### 9.1 对阶段计划的补充
- P3 增加"树莓派端录像与光控程序"：按协议自动切换光/暗、记录每帧时间戳与光照事件日志、录完自动上传。

### 9.2 第一批验证数据的具体要求（DanioVision / EthoVision）
1. 试次视频：实验文件夹下 `Media Files` 中对应试次的视频原文件（.mpg/.mp4/.avi 均可）。
2. 逐帧轨迹：EthoVision `Export → Raw data`（每个 arena 一个 .txt 或 .xlsx），包含 Trial time、X center、Y center、Area、Elongation、Distance moved、Velocity、Movement、In zone 等列。
3. 分箱结果：`Export → Analysis results`（Statistics），含分箱设置。
4. 设置截图或说明：Arena/Zone 定义、标定（像素/cm）、检测设置（Detection settings：对比度/亮度、动物大小、平滑）、Movement 起动/停止速度、Trial control（明暗协议：适应期、各相位时长、循环次数）。
5. 分组信息：哪些孔是哪组/剂量（一张表即可）。
6. 文件较大时：直接下载链接（OSS / OneDrive / Google Drive 等）最方便；≤ 100 MB 的片段可直接放进仓库；也可先给 5–10 min 的剪辑做首轮验证。
